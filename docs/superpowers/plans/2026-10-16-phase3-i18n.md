# Phase 3 — Arabic / English (full app, RTL): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen: inline, Native) to implement this plan task-by-task.

**Spec:** `docs/superpowers/specs/2026-10-16-stats-admin-i18n-design.md` (§6)

**Goal:** The whole app, clinical text included, works in Arabic or English, with a right-to-left (RTL) layout in Arabic. The SBAR export follows the app language and offers an English choice. Uploads stay in English. Arabic clinical wording is a draft and needs clinician sign-off before clinical use.

## Global Constraints
- No new dependencies; do not modify `package.json`.
- Tests live in `src/**/*.test.ts` and run in Node; no DOM tests.
- Canonical English event `label`/`detail` are part of the persisted audit trail and must not change.
- Every task ends with `npm run typecheck` and `npm test` green, then a commit.

## Core design (decisions)
1. **The audit trail stays English and keys sit alongside it.**
   - `CodeEvent` gains optional `key`, `params`, `detailKey` and `detailParams`.
   - Adding `detailKey` and `detailParams` is a spec correction: event details are clinical text, so they need translating too.
   - `label` and `detail` keep the exact English. All logic (undo, `branchFromEvents`, checklists, stats, SBAR matching) keeps matching on that English, unchanged.
2. **Params hold raw values only, never English fragments.**
   - Ids are stored as `'@'` + a message key: `{cause:'@cause.hypoxia.label'}`.
   - Numbers are stored as numbers.
   - Params named `*Ms` are durations. They render as `6m 45s` in English and as clock format `6:45` in Arabic, which avoids Arabic plural forms.
3. **The store writes English through one helper.**
   - `enText(key, params)` lives in `src/i18n/enText.ts` and imports only `en.ts`. No React is involved, and the name avoids a clash with the store's local `t` (elapsed time).
   - A golden test runs every store action and pins each English label and detail to its exact current text. Rewording the English in `en.ts` therefore can't silently change the audit trail.
4. **Displaying an event in Arabic.**
   - `eventText(e, lang)` returns the stored `label`/`detail` unchanged for English.
   - For Arabic it translates the key, falling back to the English label when the key is missing or unknown (legacy or newer-app events).
5. **Bad translation fields are dropped, never fatal.** In `sanitizeSession` (persistence.ts), a malformed `key` or `params` is removed from that one event. The session is never rejected or quarantined over display data.
6. **Language storage and detection.**
   - The language is stored in `resuscode.lang`, separate from the session.
   - If nothing is stored, it is auto-detected: `navigator.languages[0]` starting with `ar` gives Arabic.
   - `lang` and `dir` are set on `<html>` in `main.tsx` before the first render.
   - Switching language never touches the store: no `rev` bump and no session write.
7. **Dates always use the Gregorian calendar and Western digits.** One formatter does all date formatting, using the `-u-ca-gregory-nu-latn` locale extension. This replaces `toLocaleString()` in the SBAR "Generated:" line, which on an `ar-SA` phone would give a Hijri date even in the English export.
8. **Clinical content keeps a single source.**
   - `causes`, `pocus` and the post-ROSC bundle keep their English data. `en.ts` generates keys such as `cause.<id>.label|clue|action`, `pocus.<id>.view|label|meaning` and `postRosc.<id>` from that data.
   - `algorithm.ts` adds `key`/`titleKey`/`ongoingKey`, and a test pins them to the existing English.
   - Drug names, doses and units stay Latin inside Arabic, as decided.
9. **Text directions.**
   - On screen, clocks, `[MM:SS]`, dose ranges, the device id and the enrollment code field are `dir="ltr"`.
   - In the Arabic plain-text SBAR, each time is wrapped in LRI…PDI direction marks (U+2066/U+2069) so its brackets don't flip.
10. **Uploads, history storage and the CSV stay English.**
    - History capture passes `lang: 'en'` explicitly.
    - CSV headers and outcome values stay machine ids.
11. **Review markers and draft notice.**
    - Every Arabic clinical string, plus the enrollment privacy notice (consent wording), carries `// draft — clinician review required`.
    - While `AR_CLINICAL_REVIEWED = false`, Arabic mode shows a small notice: the Arabic clinical text is a draft, and English is the reference.

## Tasks (each one test-first and committed; `npm run typecheck` + `npm test` green after each)

### Task 1: i18n core
- New `src/i18n/`:
  - `lang.ts`: `detectLang`, `readLang`, `getLang`/`setLang`/`subscribeLang`, `applyDocumentLang`; uses `browserKV` from `src/engine/kv.ts`.
  - `en.ts`: `MessageKey`, the UI keys plus the generated content keys.
  - `ar.ts`: `Record<MessageKey,string>`.
  - `translate.ts`: `translate(lang,key,params)`. It never throws, resolves `'@'` keys and formats `*Ms` durations.
  - `format.ts`: `formatDateTime`, `formatDurationFor`, `ltr()`.
  - `useT.ts`: built on `useSyncExternalStore`.
  - `enText.ts`.
- Wire `main.tsx`.
- Tests:
  - every `en` key exists in `ar` with the same `{params}`, apart from a short explicit exception list;
  - `ar-SA` dates come out Gregorian with Latin digits;
  - an unknown key falls back;
  - setting the language bumps no `rev`.

### Task 2: Structured events
- Update `types.ts` and `mkEvent` with the new fields.
- Every call site in `store.ts` sets a key (start, pause and resume, cycle, rhythm check, branch, ROSC, termination, re-arrest, epinephrine, shock, amiodarone, lidocaine, magnesium, airway, cause and POCUS events — all 26 sites).
- Two events are logged from components:
  - The pulse check in `InterventionGrid.tsx` goes through `logEvent(..., i18n?)`.
  - Checklist toggles in `Checklist.tsx` log `ev.postRosc.on|off` with `item:'@postRosc.<id>'`. The English label stays identical, so `isChecklistItemOn` (`checklist.ts`) keeps working.
- `eventText()`.
- Sanitize: clean the translation fields.
- Tests:
  - the golden English test from design point 3;
  - every key renders in Arabic without leftover `{}`;
  - legacy and unknown-key events render English;
  - a malformed key keeps the session;
  - toggling a checklist item in Arabic writes the same label as in English.

## Review Focus (each gets a test in its owning task)
1. **Switching language mid-code:** the session is unchanged, `rev` is not bumped, and the whole log re-renders (tasks 1 and 2).
2. **A session from an older or newer app:** events with no key or an unknown key show their English, with no crash and no quarantine (task 2).
3. **An `ar-SA` phone:** dates are Gregorian with Latin digits, even in the English SBAR (tasks 1 and 4).
4. **A code ends while the app is in Arabic:** the uploaded SBAR and the stored history are English (task 4).
5. **A post-ROSC item ticked in Arabic, then viewed in English:** it shows as ticked, and the SBAR counts it (task 2).
